## 검증 방법 (요약 4줄)

1. 배포 주소에 로그인 없이 접속해 상단 무로그인 공개 경고 배너 문구가 정확히 뜨는지 확인한다.
2. 계획→할 일→실행(시작/완료)→회고 순서로 실제 데이터를 넣고, 새로고침해도 값이 남는지, Supabase REST API로 직접 조회해도 같은 값이 나오는지 확인한다.
3. 회고에서 남긴 통찰이 다음 계획 생성 화면의 "이어받을 회고" 목록에 뜨고, 선택해 저장하면 계획에 그 문구가 그대로 연결되는지 확인한다.
4. 소스의 `scripts/db.mjs`와 `contracts/pds-schema-v2.json`을 열어 secret/service_role 키가 없는지, 실제 테이블 구조와 계약 문서가 일치하는지 확인한다.

## AI 활용에 대한 판단 (요약 3줄)

1. 스키마 설계, Supabase 정책 작성, 프론트엔드 코드 전체를 AI(Claude)가 작성했고, 실 라이브 DB에 대한 읽기/쓰기 라운드트립까지 AI가 직접 실행해 동작을 검증했다.
2. 다만 실제 개인 데이터를 채우고 화면을 눌러보며 흐름이 어색한 부분(회고 선택 위치 등)을 짚어내는 것은 결국 사람이 직접 써봐야 나오는 피드백이었다.
3. 결론적으로 이런 CRUD+집계형 웹앱은 AI가 설계부터 배포·검증까지 대부분을 맡을 수 있지만, "실제로 써보면서 걸리는 지점을 찾는" 마지막 확인은 사람의 몫으로 남는다.
